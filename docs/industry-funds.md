# 行业资金（主力资金 / 现阶段方向）

WebUI 左侧菜单「行业资金」对应的页面与接口。把五个数据源合成一个可解释的复合信号，用来判断**现阶段方向**并给出关注方向与候选个股。

## 为什么不是直接给一个「主力资金」数字

第三方「主力净流入」是**按单笔成交金额分档推断**出来的统计值，不是账户身份。三个已知失真来源：

- **拆单**：主力把大买单拆成小单，显示「主力流出」而实际在吸筹；
- **涨停板**：封单成交常被归为卖单，出现「涨停但主力净流出」；
- **口径黑箱**：各数据商的分档阈值不公开，同一只股票不同软件能差出量级。

所以本页面的设计原则是**多源交叉验证 + 完全可解释**：每个数字都能追溯到数据源与归一化依据，而不是给一个无法验证的标量。

## 页面结构

三段，对应三个问题：

| 段 | 内容 | 回答的问题 |
|---|---|---|
| (a) 资金流向 | 同花顺 90 个行业的资金流表（当日净额 / 5 日累计 / 涨跌 / 领涨股） | 钱在往哪里去 |
| (b) 复合信号 | 大盘复合分（0-100）+ 五因子明细表 + 行业得分排行 | 现阶段方向如何 |
| (c) 结论 | 关注方向 · 关注个股 · 风险提示 · 免责声明 | 具体看什么 |

## 大盘五因子

| 因子 | 权重 | 原始值 | 归一化 | 为什么是这个权重 |
|---|---|---|---|---|
| ETF 份额变动 | 30% | 宽基 ETF 份额 5 日净增（亿份） | 历史分位（本地样本不足时退回固定标尺） | 被动资金 / 国家队的直接痕迹，日频真实资金 |
| 龙虎榜机构净买 | 25% | 近 5 日机构专用席位滚动净买额 | 近 120 个交易日滚动序列的历史分位 | 机构席位是交易所披露口径，不是概率推断 |
| 两融余额 | 20% | 全市场两融余额 5 日变化率 | 历史分位 | 杠杆情绪 |
| 行业资金流 | 15% | 净流入行业家数占比 | 占比线性映射（50% 即中性） | 受拆单干扰，故压低权重 |
| 估值分位 | 10% | 沪深300 PE 分位与全A PB 分位均值 | **反向**映射（分位越低得分越高） | 慢变量，只作背景 |

区间：**≥65 偏多 / 45–65 中性 / <45 偏空**。

### 设计要点

- **归一化的算子是历史分位，而不是拍一个阈值**。唯一例外是 ETF 份额变动：它的历史分位需要本地按日积累快照，样本不足 `ETF_DELTA_PERCENTILE_MIN_POINTS`（20）期时退回一个**有明确说明的固定标尺**（±150 亿份满量程），页面会标明当前用的是哪一种。攒够样本后自动切换。
- **某个因子抓取失败时按剩余因子重新归一权重**，而不是把它当 0 分。后者会让一次网络抖动直接变成一条看空结论。页面会显示「可用因子权重合计」并在低于 100% 时提示。
- **估值是唯一的反向因子**：分位低（便宜）得分高。

## 行业得分

统一到**同花顺的 90 个行业分类**（与 (a) 段同源），四个子因子全部是横截面分位（该值在 90 个行业中的排名）：

| 子因子 | 权重 |
|---|---|
| 当日净额 | 35% |
| 5 日累计净额 | 30% |
| 行业涨跌幅 | 20% |
| 领涨股涨幅 | 15% |

用横截面而不是时间序列，是因为同花顺行业资金流只有当日与 3/5/10/20 日排行快照，没有可用的长历史。

> **口径限制（如实标注在页面上）**：这套分类不提供成分股与行业估值，所以行业分**不含龙虎榜与估值因子**，只由资金流自身的字段构成。换用申万一级分类能拿到成分股与 PE，但与「同花顺 90 行业」不是同一套分类，两者不能混用。

## 关注个股候选池

两路入选 + 一路补充：

1. **龙虎榜机构净买** —— 当日机构专用席位净买额为正的个股；
2. **行业龙头** —— 行业分前 5 个行业的「领涨股」；
3. **同花顺个股资金流（只补充，不入选）** —— 见下方警告。

合并后**剔除所属行业资金净流出的个股**，并给每只股票记下入选路径与依据字段，用户可自行复核。

> ⚠️ **个股页的排序陷阱**：同花顺个股落地页默认按**涨跌幅**排序，不是按净额。实测涨幅榜前排的净额大量为负（拉高出货形态），所以那份数据**不能**当作「主力净流入榜」来选股。它在这里只用于两件事：给候选池的个股补充当日资金方向；把「涨了但资金净流出」的标的标记出来。

## 结论由模型生成，但模型不参与打分

数值、分位与权重全部由规则算出，模型只负责写成一段人话。三层约束防止模型编造标的：

1. prompt 里明确列出**只允许提及的个股白名单**（候选池里的代码 + 名称）；
2. 返回结果逐条比对白名单，越界的丢弃并在 `conclusion.droppedMentions` 里记录；
3. 模型不可用 / 超时 / 返回无法解析时，退回**规则化结论**（同样的数字直接拼），页面标记「规则化结论」。**结论区永远有内容，不会因为模型问题白屏。**

## 数据源与已知陷阱

改这块代码前请先读 `src/services/industry_funds/fetchers.py` 与 `ths_client.py` 的模块 docstring —— 那里记录了每个替代路径**为什么**必须这样写。摘要：

| 数据 | 来源 | 备注 |
|---|---|---|
| 行业资金流 | 同花顺**落地页**（服务端渲染） | 不用 akshare 的同花顺函数，见下 |
| 龙虎榜 | 东财 `datacenter-web` | `push2.eastmoney.com` 在部分网络被重置，不能用 |
| ETF 份额（沪） | 上交所 `commonQuery.do` 直连 | **必须传真实交易日**；akshare 的封装会返回 2025-01-15 的死数据 |
| ETF 份额（深） | 深交所 `ShowReport` XLSX 直连 | pandas 3.0 下 `pd.read_excel` 需要 `io.BytesIO`；该接口**不支持历史日期** |
| 两融 | `stock_margin_account_info`（沪深合计长历史） | 深交所接口只支持单日查询，凑 5 日序列要循环十几次 |
| 估值 | 乐咕乐股 + 全A TTM/PB | `stock_index_pe_lg` 给的是市盈率**中位数**不是分位，分位需自己算 |

### 为什么同花顺不用 py_mini_racer

同花顺的 ajax 接口要求一个由页面混淆 JS 实时生成的 `hexin-v` 请求头。akshare 用 `py_mini_racer` 在本地跑那份 JS 计算，但：

- **py_mini_racer 在本项目的并发抓取路径下会把整个进程打成 segfault**（`mini_racer.dll` + libffi，C 层段错误，Python 的 `try/except` 完全兜不住）。对 Web 服务这意味着后端进程直接挂掉，不是降级。实测主线程单次调用正常、worker 线程单次也正常，但放进真实并发抓取就复现，加进程级锁串行化也没解决。
- **用无头浏览器把 `hexin-v` 抓出来再交给后端复刻请求，行不通**：实测精确配对（同一 URL + 同一 token + 同一 cookie 罐 + 同一 UA）依然返回 `403 Nginx forbidden`，token 无法带出浏览器上下文。

最终方案是抓**落地页**——它本身是服务端渲染的，用普通 `requests` 就能拿到含完整数据表格的 HTML，**不需要任何 token**。分页走 `/page/N/` 路径（`?page=N` 查询串无效，会返回第 1 页）。

## 刷新为什么走后台任务

全量刷新并行访问约 6 个上游再调一次模型，实测 30~90 秒，而前端 HTTP 客户端超时是 30 秒。所以：

- `POST /api/v1/industry-funds/jobs` 提交后台任务，返回 `jobId`；
- `GET /api/v1/industry-funds/jobs/{jobId}` 轮询进度；
- `GET /api/v1/industry-funds/overview` 只读缓存，秒回。

**冷却期**：两次刷新之间强制间隔 `INDUSTRY_FUNDS_REFRESH_COOLDOWN_SEC`（默认 60 秒）。上游对频率敏感，且同一天重复刷新会污染 ETF 份额分位的样本，所以连点刷新时复用进行中的任务或直接提示等待，**force 也不跳过冷却**。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/industry-funds/status` | 模块是否启用（菜单据此显示/隐藏） |
| GET | `/api/v1/industry-funds/overview` | 读缓存快照；无缓存返回 404 |
| GET | `/api/v1/industry-funds/history` | 最近若干份快照摘要 |
| POST | `/api/v1/industry-funds/jobs` | 提交刷新任务 |
| GET | `/api/v1/industry-funds/jobs/{jobId}` | 轮询任务 |
| GET | `/api/v1/industry-funds/jobs` | 当前进行中的任务（页面重连用） |
| POST | `/api/v1/industry-funds/push` | 推送结论到已配置的通知渠道 |

## 配置

见 `.env.example` 的「行业资金」小节。全部可用默认值运行；`INDUSTRY_FUNDS_PUSH_ENABLED` 默认 `false`，避免误发。
