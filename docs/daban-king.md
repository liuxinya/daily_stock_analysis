# 我是打板王（短线世界观、盘中评分推荐与复盘）

「我是打板王」把 `92科比` 与 `陈小群` 两位游资公开分享的短线理念做成一套工具：

- **盘后**：判定情绪周期，过连板梯队与主线题材，生成一份两派共用的**短线世界观**（给下一个交易日用的边界、节点和各维度结论）和**次日观察清单**。盘后不出推荐。
- **盘中**：雷达在热点题材里找用户**还买得进**的票，按回测标定的**计分表**评分，总分达标的进入「重点」并记成本、记成绩；已经封住的票放进「涨停板」，龙 1 / 龙 2 置顶。
- **复盘**：每只推荐按 H1 卖法回填成绩，初始分到收盘分逐项归因，世界观逐维度对账，每月用新数据重标计分表。所有改动由用户确认后才改（科比 #22「要不断的修正自己的错误」）。

理由都挂理念条目的出处，悬停可看原文摘句。摘句全部是两篇原文的原话（`tests/test_daban_principles.py` 在本地有原文时逐字核对）；原文没有出处、但回测有效的计分项标「系统补充」。

> 这是规则化的复盘工具，不是荐股系统，不给仓位建议。两篇原文的观点只代表作者个人，陈小群那篇还是第三方整理稿；页面与推送都会附免责声明。

## 设计原则

1. **周期先于个股**。情绪周期决定能不能做；之后才轮到选股。冰点、退潮、主跌第 1 天管住手。
2. **两派融合，不分线**。两派原文的目的都是找胜率、收益更高的打法。原文和回测冲突时，回测逻辑「够硬」就按回测走，否则按原文走（见「取舍原则」）。
3. **推荐有硬依据，不靠猜**。计分项必须先在一年回测里证明有区分度；没有区分度的原文因子只当理由展示、不进分数。
4. **硬边界，盘中可修正**。昨天收盘的结论只是开盘的起点。盘中大盘急拉、题材异动、新题材出现时，只放开触发的那个方向。
5. **全部记成绩，不前视**。进入「重点」的每一只都记成绩；评判推荐行为只用推荐时刻之前的数据，之后发生的事单独列为「当时不可知」。
6. **规则为主，模型只写判断**。模型只写大局观和各主线题材的预期判断，不改任何规则结论。

### 取舍原则（2026-11-08 定）

「够硬」指同时满足：不前视；样本够（个股级 ≥200 次且覆盖 ≥50 个交易日，市场级 ≥15 个交易日）；前后半段同号；差距够大（个股级超额 ≥0.3 个百分点，市场级 ≥2 倍标准误）；说得通（能用原文或交易机制解释，事后发现的先过一次样本外检验）。

| 冲突 | 原文 | 回测 | 结论 |
| --- | --- | --- | --- |
| 退潮期 / 主跌第 1 天遇「龙头见顶杀高位」 | 陈小群「退潮期坚决空仓」 | 15 天按天 +0.86%，前后半段 +1.09% / +0.59%；同为退潮、没有该节点的 30 天 -0.19% | 按回测，照常推荐 |
| 「低位已有赚钱效应」节点 | 科比 #14 | 三种定义都没有区分度 | 按回测，去掉 |
| 冰点、其余退潮日 | 陈小群 | 不支持放开 | 按原文，管住手 |
| 4 种一进二情形 | 科比 #12「低位就是做首板或者一进二」 | 胜率 41~49%，前后半年都为负，已够硬 | 先按原文照常推荐、不扣分，进**观察期**，成绩单独成组，首次月度重标时用实盘数据复核 |

## 页面结构

**盘后复盘**（复盘顺序：科比 #38 先过涨停，陈小群「周期定位 → 主线识别 → 龙头确认 → 信号等待」）：

1. **情绪周期**：陈小群六阶段 + 科比四阶段、八个指标卡、近 10 个交易日的阶段条带（点击回看）、六阶段条件核对表。
2. **连板梯队**：从最高板往下排，层间标分层晋级率。
3. **主线题材**：排名、涨停数、最高板、持续天数、状态、新老题材、**成员共性**、故事空间与明天的**预期判断**（模型写，只展示）、近 3 日新闻。
4. **短线世界观**：明天的边界、大局观、11 个维度的结论（每项注明作用与出处），以及昨天那一份世界观的对账和近 20 份的累计准确率。
5. **次日观察清单**：盘后的七种战法候选只当观察对象，列触发 / 放弃条件；明天盘中满足条件时由雷达统一评分。
6. **「重点」成绩单**：近 20 个交易日分组成绩（H1 / 次日开盘卖 / 次日收盘卖），计分项实盘准确率，观察期复核，今天每一只推荐的初始分→收盘分、逐项归因、当时不可知的事件、漏掉的个股新闻。
7. **排除名单**、**首板预判跟踪**、免责声明。

2026-11 之前生成的复盘没有世界观，页面提示重新生成；那些快照里的「打法裁决」「两条推荐线」原样保留在库里，接口照旧透传，页面不再展示。

**盘中雷达**（`/daban-king?tab=live`，交易时段默认打开，每 10 秒刷新）：

1. **今天能不能推荐**：世界观边界（可以推荐 / 部分放开 / 管住手 / 停发）、原因、今天触发的推翻信号、边界改动记录、实时周期重判、前一交易日的判定依据。
2. **刚刚发生**：最近 30 分钟的封板 / 回封 / 炸板事件。
3. **今日主线题材**：热点题材卡片（按热度红→蓝），涨停数、连续天数、新闻、成员共性、补涨是否结束、「重点」里有几只；点击筛选。
4. **「重点」/「涨停板」两个 tab**（见下文）。
5. **计分表**：每一项的分值、出处或「系统补充」、标定时的回测数字；观察期情形。

## 情绪周期

### 指标（统计口径：沪深主板 + 创业板 + 科创板，剔除 ST；北交所默认不含）

| 指标 | 口径 |
| --- | --- |
| 涨停家数 | 收盘封住涨停 |
| 连板支数 / 连板高度 | 连板数 ≥2 的股票数 / 当日最高连板数（来自同花顺连板天梯） |
| 连板晋级率 | 今日连板数 / 昨日涨停数；分层晋级率按昨日板数分组 |
| 昨日涨停今日表现 | 昨日涨停股今日等权平均涨跌幅与上涨占比（东财 `getYesterdayZTPool`） |
| 大面股 | 昨日涨停今日跌幅 ≤ -5% |
| 炸板率 | 炸板 / (涨停 + 炸板) |
| 龙头封单比 | 最高板封单金额 / 流通市值 |
| 主线集中度 | 第一题材涨停数 / 总涨停数（原文「跟风率」没给口径，这是本功能的解释） |

### 六阶段判定（透明投票）

| 阶段 | 条件（默认阈值） | 原文仓位上限（只作引述，系统不给仓位建议） |
| --- | --- | --- |
| 冰点 | 涨停 <30；连板 <5 支；昨日涨停今日 ≤ -2% | 0 |
| 回暖 | 涨停 30–50；连板 5–8 支；晋级率较昨日上升 | 10–20% |
| 发酵 | 涨停 50–80；连板 8–12 支；主线集中度 >30% | 30–50% |
| 高潮 | 涨停 >80；高度 ≥5 板；龙头封单比 ≥3% | 50–80% |
| 分歧 | 涨停较昨日减少；高度回落；大面股增多 | ≤30%，只卖不买 |
| 退潮 | 跌停 >10；连板 <3 支；昨日涨停今日 ≤ -3% | 0 |

- 命中率最高者胜；数据缺失的条件按未命中计。平局时取与昨日阶段相邻的，没有昨日阶段时取更保守的（先认亏钱阶段）。
- 最高命中率 < 2/3 时标「过渡态」。
- 跌停 > 20 家直接判退潮（陈小群：>20 家明确退潮）。
- 科比四阶段由六阶段映射（冰点 / 回暖 → 低位震荡，发酵 / 高潮 → 主升，分歧 → 高位震荡，退潮 → 主跌），主跌再按「连续杀跌第 N 天」细分（杀跌日 = 退潮或冰点且昨日涨停溢价为负）。

**阈值要人工校准**：陈小群那篇是第三方整理稿，数字对应的是约 4000 只股票的年代（现在约 5400 只）。全部阈值都可以用 `DABAN_RULES_FILE` 覆盖。

## 主线题材与个股角色

- **归因**：同花顺涨停池每只股票带「涨停原因」（如 `PCB+AI服务器+HDI板`），按 `+` 切成标签，剔掉业绩、订单、增持这类公司自身催化，再按「互相包含」合并：两两标签的公共后缀（≥3 字，如「人形机器人 / 工业机器人」→「机器人」）作为核心词把它们并到一起。同义但字面不沾的合并留给模型。
- **主线**：按 `涨停数 + 2×连板数 + 最高板` 排名，前 3 且涨停 ≥3 只为主线。
- **持续天数**：取同花顺题材榜的连续上榜天数，与本地历史「每天至少 2 只涨停」的连续天数取大。
- **新 / 老题材**：与近 10 个交易日的主线比字面：同名为老题材，字面相关为共性发散，都不沾为新题材。计分表的「老题材」格子按这个口径标定，所以保留；世界观另按**成员**判共性（见下文）。
- **角色**：总龙头（全市场最高板，并列时依次比 N 天 M 板里的 M、首封时间、人气榜）、板块龙头、前排（2 板或首封最早的 3 只首板）、低位补涨（低价小盘）、**中位股**（3 板到最高板 − 1，排除，科比 #12）、**跟风**（主线里非前排且不够低价小盘，排除，陈小群「只做龙头不做杂毛」）。

## 短线世界观（`src/services/daban/worldview.py`）

一份每天更新的结构化结论，两派共用。框架取 Sleep交易员的 11 个维度，判定标准取 92科比、陈小群的原文，原文没给标准的用回测定，定不了的由模型写判断、不决定结果。

- **盘后版**：收盘后生成，存进快照 payload 的 `worldview`，`for_date` 是下一个交易日。
- **盘中版**：以盘后版为起点。只有三种情况能改结论：实时周期重判（市场验证）、推翻信号、停发新推荐。每次改动记一条（时刻、改前改后、原因），写进 `daban_radar_events`（`kind=worldview`）。前一交易日没有盘后版（没生成复盘）时，雷达用门控数据现拼一份，页面注明。
- 每只票进入「重点」时，把当时的边界结论存进推荐记录的初始快照，复盘时用。

| 维度 | 怎么判 | 作用 |
| --- | --- | --- |
| 赚钱效应 | 昨日涨停今日均涨幅、上涨占比、大面股、炸板率 | 周期判定的输入；盘中实时门控 |
| 周期 | 陈小群六阶段投票；科比四阶段，主跌按「连续杀跌第 N 天」 | 边界：冰点、退潮、主跌第 1 天不推荐 |
| 情绪 | 市场核心 = 全市场最高板；板块核心 = 各题材龙 1 / 龙 2 | 「涨停板」tab 的标记 |
| 主线 | 盘后：涨停数 + 2×连板数 + 最高板前 3 且 ≥3 只；盘中：热点题材三道门槛 | 资格：不在热点题材里不推荐 |
| 龙头 | 板数 → N 天 M 板里的 M → 首封时间 → 人气榜 | 龙 1 / 龙 2；跟风扣分 |
| 补涨 | 和近期主线共性相同的非主线题材；补涨结束按科比 #6 | 补涨结束后该题材停推 |
| 切换 | 和近期主线共性不同的题材 | 新题材只在原文时机推荐 |
| 节点 | 龙头见顶杀高位、高位分歧、主跌之后（开盘前可知） | 节点日标记；新题材时机；退潮期遇龙头见顶杀高位照常推荐 |
| 预期 | 昨日涨停股按「板数 × 板质量」对历史开盘分位（09:25 后） | 标签；题材和龙头的预期判断 |
| 弱转强 | 弱 = 炸板 / 开过板 / 14:30 后封板；强 = 被买上去、扫板、板块配合 | 计分项「昨日炸板今天高开 2~5%」；其余在盘中留档验证 |
| 大局观 | 三大指数涨跌（规则）；综合判断由模型写 | 只展示；指数急拉是推翻信号 |

### 边界与放行

| 情形 | 依据 | 处理 |
| --- | --- | --- |
| 前一交易日收盘是冰点 / 退潮 | 陈小群 C02 / C10 / C16 | 管住手 |
| 前一交易日是主跌第 1 天 | 科比 #9「第一天杀跌是很恐怖的」；回测 16 天按天 -0.47% | 管住手 |
| 退潮 / 主跌第 1 天，且今天是「龙头见顶杀高位」节点 | 科比 #9；回测见「取舍原则」 | 照常推荐，卡片标「节点日」（冰点不放行） |
| 盘中实时周期连续确认、今天的周期不在冰点 / 退潮 | 陈小群「预判必须得到市场验证」 | 放开全部 |
| 大盘急拉推荐点触发（沪深300 30 分钟 ≥0.8 且翻红） | 回测见「大盘急拉推荐点」 | 只放开触发后 30 分钟，票标「未验证」（这种日子一年只有 7 天样本） |
| 推翻信号：大盘指数急拉 | 回测里放开的票每笔 H1 -0.21（22 天） | **只提示、不放开** |
| 推翻信号：题材异动 / 新题材出现 | — | 只放开那个题材 |
| 盘中赚钱效应回落且没有题材在接力 | 沿用实时门控的降级 | 停发新推荐，已进入的照常记成绩；推翻信号放开的题材除外，大盘急拉不解除停发（它推翻的是前一交易日的周期边界） |
| 中位股：昨日 2 板今天冲 3 板 | 科比 #12；回测 1040 次 -0.88% | 个股级挡掉 |
| 新题材不在原文时机 | 科比 #9 / #14 | 个股级挡掉，只观察 |
| 补涨结束 | 科比 #6：低位补涨股隔日亏钱，且龙头没有反包 | 该题材停推 |

**节点**（只用 D-2、D-1 的池子，开盘前可知）：龙头见顶杀高位 = 前天的最高板（≥3 板）昨天跌 ≥5%；高位分歧 = 昨天的最高板低于前天；主跌之后 = 昨天是主跌第 2 天及以后。

**共性按成员判**：题材当下成员（涨停原因相关的涨停股 + 题材榜成员）近 90 天的涨停原因落在近 10 日主线里的比例，≥50% 算共性相同（补涨 / 发散），≤20% 算共性不同（新题材 / 切换），中间算部分相同。比字面可靠：同一共性换个名字字面对不上，成员的历史涨停原因对得上。没有近期主线可比时记「无法判断」，不当成新题材挡掉。阈值是起始值，在 `rules["worldview"]`。

### 推翻信号（暂定阈值）

| 信号 | 判定 | 放开 |
| --- | --- | --- |
| 大盘指数急拉 | 上证 / 深成 / 创业板 30 分钟内拉升 ≥ 0.8 / 1.0 / 1.5 个百分点，且当前为正 | 不放开，只提示（`overrides.index_opens=false`） |
| 题材异动 | 某热点题材 15 分钟内新增封板 ≥3 只 | 那个题材 |
| 新题材出现 | 成员共性不同、涨停 ≥4 只，且今天在原文时机上（节点日） | 那个题材 |

触发后当天不收回（重启后从留档恢复）。阈值在 `rules["overrides"]`，**是暂定值**，要用 `daban_radar_events` 攒下的盘中数据校准；页面标「阈值暂定」。

### 大盘急拉推荐点（`rules["surge_point"]`）

**判定**：沪深300 近 30 分钟拉升 ≥0.8 个百分点，且此刻翻红。参考点只用 09:35 之后的分时（开盘跳空不算），所以最早 10:05 能触发；当天只认第一次，重启后从留档（`kind=surge`）恢复。

**作用**：买入时机的提示，**不改评分、不单独统计成绩**；只在被挡住的日子放开那 30 分钟（见下）。

- 触发后 30 分钟内新进入「重点」的票打「大盘急拉推荐点」标记，在「重点」tab 最上面单独置顶（题材分组里不再重复），推送标题带这个标记；
- 触发时页面顶部出横幅（触发时刻、拉升幅度、标记截止时刻），开了 `DABAN_LIVE_PUSH_ENABLED` 时另推一条（按交易日去重）；
- 被前一交易日周期挡住的日子（冰点 / 退潮 / 主跌第 1 天）：**只在这 30 分钟里放开推荐**，进入的票另标「未验证」；窗口过后照常挡住。停发新推荐仍然优先。

**依据**（2025-12 ~ 2026-11，5 分钟线回测，H1 卖法，未扣交易成本）：一年约 28 天触发；开放的日子里，触发后 30 分钟内进入的票每笔 H1 +1.81%、胜率 69%（17 天，前后半年 +1.70 / +1.88）；进入时正在急拉的票当天收盘胜 72%、次日开盘卖胜 61%、次日收盘卖胜 71%。触发之后更晚才进入的只有 +0.73，所以只标这 30 分钟。天数不多，月度重标时复核。

**和推翻信号「大盘指数急拉」的对比**（同一批回测，只算总分 ≥0 的候选）：推翻信号一年触发 88 天，其中 22 天落在被挡住的日子，平均比推荐点早约 1 小时；它在被挡住的日子放开的票 H1 胜率 58.6%、每笔 -0.21 ± 0.35、次日收盘卖胜率 43.6%，其中不在推荐点窗口里的 -0.30。推荐点窗口里的同类票（7 天）胜率 67%、每笔 +0.80 ± 0.96。所以大盘指数急拉改成只提示，被挡住的日子只由推荐点窗口放开；`overrides.index_opens=true` 可以恢复旧行为。全年数据用 ETF 代替指数（510210 / 159903 / 159915 / 510300），按 5 分钟线判断触发，实盘轮询更密，推翻信号会触发得更早更频繁。

### 次日对账

用第二天的实际结果核对前一天的世界观：周期（判回暖 / 发酵 / 高潮，第二天昨日涨停溢价是否为正）、主线（是否仍在前 3）、龙头（龙 1 是否仍是题材最高板）、切换（标为新题材的涨停数是否增加）、补涨（低位补涨是否赚钱）。逐维度累计近 20 份的准确率；偏离时由你决定要不要改规则。

## 盘中雷达：「重点」与「涨停板」（`live.py` / `recommend.py`）

### 候选从哪来

- **涨停池 / 炸板池**（同花顺）：池里的票盘口现价低于涨停价，按「炸开」处理；
- **东财拉升异动**「火箭发射 / 快速反弹」最近 10 分钟（涨幅 ≥3%）；
- **全市场扫描**：每 60 秒用腾讯批量行情扫一遍沪深主板 + 创业板 + 科创板（约 5200 只、9 批，实测约 1.4 秒，后台线程跑），补上慢慢涨上来、没触发异动的票（涨幅 ≥2%）。

共同门槛：非 ST、非北交所、股价 ≥2 元、流通市值 ≤500 亿、距涨停 ≤6%。东财异动在 09:30 后几分钟常超时，取数失败时沿用 90 秒内的上一份，页面标注。

**题材归属**：当日涨停原因 → 近 90 天历史涨停原因 → 当日题材榜成员 → 东财所属概念（只对前三级都没贴上的查），落到今日热点题材的 key 上。热点题材 = 够热（涨停 ≥3 只或占全市场 ≥5%）+ 在升温（连续上榜 ≥2 天或比昨天多）+ 有新闻（近 3 日 ≥3 条，新闻不可用时降级放行）。

### 「重点」：要记成绩的票

同时满足四条才进入：

1. **还买得进**：没封板且距涨停 ≤6%，或封过板后炸开、现价低于涨停价；
2. **属于当下热点题材**；
3. **没被世界观边界挡住**（见上文）；
4. **总分 ≥0**（评分体系 v2 的门槛）。

- **一只票一天只记一次**：第一次进入那一刻的现价就是**成本**，初始分、各计分项、格子、股性、当时的边界结论和行情当场存进 `daban_recommendations`，之后不改。
- **实时分**每轮重算，变化时记一条 `score` 事件；收盘时最后一次的分数记为**收盘分**。进入后不撤回：分数掉到 0 以下也留在列表里，标「已降分」，照样计成绩。
- **不设数量上限、不给仓位**。同一题材内按实时分从高到低，同分按距涨停从近到远（回测里离涨停越近买，次日表现越好）。
- 卡片显示：总分（实时 / 初始）、进入时刻、成本、现价、距涨停、浮盈、状态（未封板 / 炸开 / 已封住）、逐项明细（出处或「系统补充」）、股性标签和风险提示，以及「观察期」「已降分」「回测未覆盖」「炸开后进入」「节点日」「推翻信号放开」「大盘急拉推荐点」标记。
- 热点题材里没进「重点」的候选折叠列出原因：分数不够、边界挡住、中位股、新题材不在时机、补涨结束、日 K 还在取……
- 集合竞价（09:15–09:30）只留档、不推荐。
- 特征要用日 K：雷达当天第一次运行时后台准备昨日上下文（D-1 涨停 / 炸板池、D-2 涨停池、近 10 日主线、近 90 天涨停原因；库里没有的日子从同花顺补），并预取昨日涨停 / 炸板票的日 K；其余候选进入视野时后台现取。**取到之前不进「重点」**，避免初始分残缺。近一年没摸过涨停价的票标「回测未覆盖」。

### 「涨停板」：已封住的票

按热点题材分组，每组龙 1 / 龙 2 打标记放最上面（板数 → N 天 M 板 → 首封时间）。不评分、不记成绩；被推荐过的标「已推荐」；附连板成功率（科比 #29：看风向标明天有没有人接）、封单、开板次数。

### 推送

`DABAN_LIVE_PUSH_ENABLED=true` 时，有票**新进入「重点」**就推送：总分、进入时刻与成本、命中的计分项及出处、观察期说明、股性、节点日放行理由、H1 卖法。按「交易日 + 代码」去重，不含仓位。

## 评分体系（v2，2026-11-08 定稿）

**回测口径**：模拟「盘中拉升到距涨停 6% 时按现价买入」，买入时只用那一刻已知的信息（昨天收盘以前的日线、昨天的池子与题材、近 90 天涨停原因、今天的开盘价）。2025-12-04 ~ 2026-10-19，209 个交易日、89901 次买入；按 H1 卖出，基准平均 +0.09%、胜率 56%、当天封住 13%。

**分值**：H1 收益相对基准的超额，每 0.1 个百分点记 1 分，小样本向 0 收缩，单项封顶 ±20。0 分 = 同批候选的平均水平。入选条件：样本 ≥200、覆盖 ≥50 个交易日、前后半段同号、|超额| ≥0.3 个百分点。总分范围 -31 ~ +5。

| 情形 | 出处 | 分 |
| --- | --- | --- |
| 昨日没触板，今天高开 ≥5% 但没涨停 | 科比 #34「弱转强不喜欢竞价高开」 | -8 |
| 所属题材第 1~2 天，但属于老题材 | 系统补充 | -8 |
| 20cm 且股价 10~20 元 | 系统补充 | -6 |
| 20cm 且股价 20~40 元 / ≥40 元 | 科比 #27「低价为王」（20cm 是系统补充） | -5 |
| 昨日量比 ≥3 倍（对前 5 日） | 系统补充 | -5 |
| 20cm 且股价 5~10 元 | 系统补充 | -4 |
| 和题材龙头近 40 日相关系数 ≥0.7 / 0.5~0.7，题材第 1~2 天 | 陈小群 C13「只做龙头不做杂毛」 | -4 |
| 昨日没触板，今天高开 2~5% | 系统补充 | +5 |
| 昨日炸板，今天高开 2~5% 后被买上去 | 陈小群 C04 弱转强 | +4 |

- 样本外（前半段定分、后半段检验）：总分 <0 的占 16%，平均 -0.42%；≥0 的占 84%，平均 -0.08%、胜率 55.3%。**排除坏票做得到，挑出好票做不到**——决定盈亏的信息在盘中（当天封住的平均 +7.55%，没封住的 -1.01%），要靠盘中留档验证后再升为计分项。
- **观察期**：昨日首板（硬板 / 弱板）今天低开后被拉起、昨日首板（硬板）今天高开 ≥5% 未涨停、昨日首板（硬板）今天高开 2~5%，按回测本应扣 -11 / -7 / -6 / -3 分。照常推荐、不扣分，卡片标「观察期」，成绩单独成组。
- **股性**（科比 #29 + 冲板封住率）：只当标签，不进分数。冲板封住率 ≥35% 标「活跃」（更容易封住，但没封住时跌得更深，H1 反而更差），10~35% 「一般」，<10% 「不活跃」；附「近一年冲板 N 次、封住 M 次、没封住的次日平均」。涨停板 tab 的龙头附连板成功率。
- **周期不进分数**：按天聚合后六阶段、四阶段都没有一档显著，只作边界。
- 特征计算在 `src/services/daban/rec_features.py`，**回测与盘中共用**；计分表在 `rules["rec_score"]`，可用 `DABAN_RULES_FILE` 整表覆盖。用同一份缓存重放，`rec_features` 算出的 89901 个事件与定稿研究脚本逐个对得上（跟风相关系数分档有 41 个浮点边界差异，H1 有 3 个）。

## 成绩与复盘

### 卖出口径（H1 为主）

- **H1**：买入当天收盘封住的，按科比 #25 不涨停当天收盘卖、涨停继续拿（最多到第 5 天，期间为「持有中」）；没封住的，次日高开（开盘价 ≥ 成本）就在开盘卖，低开等到收盘卖。
- **对照**：次日开盘卖、次日收盘卖。
- 一字跌停卖不出去时顺延到下一个交易日开盘。是否封住以收盘涨停池为准。成绩按不复权日 K 算（成本是当时的真实成交价）。
- 回填：雷达每 10 分钟最多回填一次（后台线程），收盘复盘也会回填；只用已经收盘的 K 线。

### 收盘复盘（「重点」成绩单）

- **收盘对账**：收盘分 = 最后一次实时分；写入是否封到收盘。
- **分组成绩**（近 20 个交易日）：全部、计分推荐 / 观察期、总分 >0 / =0、节点日、炸开后进入、按股性；每组给封住率与三种卖法的平均和胜率。
- **计分项实盘准确率**：每个计分项的实盘 H1 超额对回测超额，样本 ≥20 且方向相反时提示「建议复核」。
- **观察期复核**：观察组 ≥30 只、≥10 个交易日后，和其余推荐比；更差就建议按回测扣分，相反就建议保留。只出建议，由你确认。
- **逐只归因**（不前视）：
  - 初始分到收盘分逐项变化；
  - 推荐之后才发生的封板 / 炸板 / 回封、之后发布的新闻，列为「当时不可知」，不算判断错误；
  - 推荐之前已经发布、但评分体系当时没纳入的个股新闻（按 `published_at` 筛），列为「漏项」，用来决定要不要补这个数据源。

### 月度重标与盘中因子评估

```bash
python scripts/daban_backtest.py                  # 先把缓存补到最新（首板 / 一进二回测）
python scripts/daban_backtest.py --mode recommend # 推荐计分表月度重标 → data/daban_backtest/report/recommend.md
python scripts/daban_backtest.py --mode intraday  # 盘中因子评估 → data/daban_backtest/report/intraday.json
```

- `--mode recommend`：用同一份 `rec_features` 重放一年，按入选条件重算计分表，和当前规则逐项对比，输出「建议变更清单」、当前表和样本外的效果、观察期的回测与实盘复核。**只出建议，不改规则**；确认后写进 `DABAN_RULES_FILE`。
- 候选计分项（`rec_backtest.CANDIDATE_ITEMS`）：定稿之后才发现、还没进计分表的项，每次重标都在「总分 ≥ 门槛」的推荐里按同一套入选条件复核一次，满足了也只进建议清单。目前一项：10cm 股性活跃（近一年冲板封住率 ≥ 35%）。2026-11 用一年数据复核：487 次 / 179 天，超额 -0.56 个百分点，前后半段 -0.19 / -1.02，满足入选条件，建议 -4 分，等你确认。
- `--mode intraday`：用 `daban_radar_events` 里每只热点候选第一次进入视野的那一刻（现价、量比、换手、今开幅度、触发时段）当买点，按 H1 回填，按「样本 ≥300、覆盖 ≥20 个交易日、前后半段同号、超额 ≥0.3 个百分点」筛候选计分项。样本不够时如实报「样本不足」，按每天 50~100 个候选估算要 4~6 周。

## 盘中时序留档（`daban_radar_events`）

评分体系里的「盘中因子」（涨速、换手、扫板、题材实时封板数、龙 1 / 龙 2 状态、大盘指数）日线回测测不到，只能靠雷达按时刻攒数据，攒够 4~6 周再验证。所以 09:30 之后每一轮刷新都往这张表追加事件，**只增不改**：

| `kind` | 什么时候写 | 内容（`data`） |
| --- | --- | --- |
| `seen` | 一只票当天第一次进入候选 | 状态、涨幅、换手、量比、卖一量、今开幅度、流通市值、首封时间、`hot` 标它是否在今日热点题材里 |
| `seal` / `open` / `reseal` | 热点候选封板 / 炸板 / 回封 | 首封时间、开板次数、封单 |
| `sample` | 热点候选里还没封住的，每 5 分钟一次（不论它这一轮还在不在异动列表里） | 现价、距涨停、涨幅、换手、量比、卖一量、日内最高涨幅 |
| `theme` | 每 5 分钟 | 热点题材名单与各题材龙 1 / 龙 2 的板数、首封时间、开板次数、封单、是否封死（`code` 为空） |
| `market` | 每 1 分钟 | 上证 / 深成 / 创业板 / 科创 50 实时涨跌（腾讯行情），全市场涨停 / 炸板 / 跌停、昨日涨停溢价、炸板率，实时门控是否升级 / 停发（`code` 为空） |
| `auction` | 集合竞价期间每 1 分钟 | 昨日涨停 / 炸板票的竞价价格、涨幅、成交量（陈小群弱转强「竞价从负转正，量能是前一日同期 3 倍以上」） |
| `focus` / `score` | 进入「重点」那一刻 / 之后实时分变化 | 分数、命中的计分项、观察组、进入时状态；分数变化前后 |
| `override` / `worldview` | 推翻信号触发 / 世界观边界改动 | 信号内容与阈值；改前改后与原因（`code` 为空） |
| `surge` | 大盘急拉推荐点触发（当天一次） | 指数、触发时刻、标记截止时刻、拉升幅度与阈值（`code` 为空） |

- **候选口径不看边界和分数**：涨停池 + 炸板池 + 距涨停 ≤6% 的未涨停候选（异动 + 全市场扫描）。冰点、退潮这些管住手的日子不推荐，但这些天的样本正是之后验证「要不要放行」需要的。
- 冷门票（不在今日热点题材里）只记一条 `seen`；之后进了热点会再记一条 `hot=true` 的 `seen` 并开始跟踪。
- 集合竞价期间也记（09:15 起）。精度受轮询间隔限制：开着页面约 10 秒，只有后台任务时约 30 秒。留档在后台线程写，上一轮没写完就跳过这一轮（变化下一轮照样补上），不拖慢页面。进程重启后从库里恢复当天状态，不重复写 `seen`。
- 间隔与开关在规则 `radar_log` 下（`enabled`、`sample_sec`、`theme_sec`、`market_sec`、`auction_sec`），可用 `DABAN_RULES_FILE` 覆盖；纳入 `DABAN_RETENTION_DAYS` 保留策略。留档失败只记日志，不影响雷达。
- 量级：每天约 100 个热点候选 × 采样 + 状态变化 + 题材 / 大盘快照，约 5000~8000 行。

## 模型只写大局观与题材预期

模型一次调用：一句话结论、大局观（指数、周期、主线、节点合在一起怎么看）、每个主线题材的故事空间、与近期主线的共性说明、明天的预期判断（什么算超 / 低于预期、各怎么应对），以及风险提示。约束：

- 输出只展示，不改周期、边界、计分；不推荐个股、不给价位或仓位；
- 提及个股只能用题材成员白名单里的代码，越界代码被抹掉并记入 `dropped_mentions`；只能引用理念条目库里的 id；
- 新闻标题用 `BEGIN/END_UNTRUSTED_NEWS_ITEMS` 包裹，当作不可信文本；
- 模型不可用、超时、返回空或无法解析时退回规则化文字（故事空间按新闻条数与涨停规模估计），页面标「规则兜底」。

输出预算是 16384 token：deepseek-v4.1-flash 即便 `reasoning_effort=low` 也会先吃掉 5k–8k reasoning token。

## 首板回测（`scripts/daban_backtest.py`）

两篇原文对首板只有定位：科比「低位就是做首板或者一进二」（#12）、「根据新闻去挖掘一些票」（#38），陈小群回暖期「聚焦新题材首板/二板」。没有任何量化标准，所以在定首板规则之前先用历史数据回放。

```bash
python scripts/daban_backtest.py                               # 同花顺可回溯的全部区间（约一年）
python scripts/daban_backtest.py --start 2026-04-01 --end 2026-10-20
```

数据缓存在 `data/daban_backtest/`（不入库），报告写到 `data/daban_backtest/report/report.md`。周期、题材、角色直接复用线上模块，与页面口径一致。三种买法：

- **首板打板**：盘中第一次触板以涨停价买入，**不论最后封没封住**（只看封住的首板是幸存者偏差）。环境特征取前一交易日收盘。
- **一进二**：首板次日盘中触板、且不是一字（买得到）时以涨停价买入；首板当天的特征与次日开盘幅度都是买前已知。
- **炸板次日**：炸板当天收盘买入，用来检验「从炸板股里预判明天首板」。

卖出：当天涨停多拿一天（科比 #23），否则卖（#25），同时给开盘卖与收盘卖两个价。收益是理论成交，未计费用、滑点，也没有模拟排板买不到。

2025-10-09 ~ 2026-10-20（250 个交易日）的主要结论：

| 买法 | 样本 | 结果（次日开盘卖） |
| --- | --- | --- |
| 首板打板 | 18263 次触板 | 封住率 72%；均值 +0.67%、胜率 46%。封住 +2.65%，炸板 −4.40%，盈亏几乎全由「封不封得住」决定 |
| 一进二 | 13519 只首板，可买 21% | 均值 −0.31%、胜率 40%（收盘卖 −0.91%）。没有任何特征分组显著为正 |
| 炸板次日 | 6229 只 | 次日涨停 7.8%；收盘卖均值 −0.54%，几乎所有分组为负 |

- 与原文一致：首板打板在「主跌第 2 天」均值 +1.95%（316 例，前后半段都为正），「主跌第 1 天」−0.08%，对应科比 #9；一进二次日高开 ≥9%（含一字）−1.32%，对应 #35「一字板对接力不友好」；尾盘首板做一进二 −2.09%；股价 ≥40 元的一进二 −0.91%，低价（<10 元）为正，对应 #27「低价为王」。
- 与直觉不一致：一进二里「新题材」−0.79%（t = −3.1），「老题材」+0.19%；陈小群「回暖期聚焦新题材首板/二板」在回暖期样本只有 154 例，前后半段方向相反，数据不足以支持或否定。
- 盘中可知的题材信息（历史涨停原因是否命中昨日主线）对首板打板几乎没有区分度；收盘后的题材聚类区分度很高，但那是前视信息，不能用来定盘中规则。

这份回测是早期「打板价买入」口径；推荐评分用的是「距涨停 6% 按现价买入、H1 卖出」口径（见「评分体系」与 `--mode recommend`）。当前版本**没有**加入「首板预判」模式：基于炸板股的预判在数据里是负收益；科比原文的预判是「先于市场发现可发酵的舆论事件」，依赖新闻，现有历史数据无法回测。

## 数据源与已知陷阱

| 数据 | 主源 | 兜底 |
| --- | --- | --- |
| 涨停 / 炸板 / 跌停池 | 同花顺 `data.10jqka.com.cn/dataapi/limit_up/{limit_up_pool,open_limit_pool,lower_limit_pool}`（无 token，支持历史日期，带涨停原因、N 天 M 板、封板率） | 东财 `push2ex` `getTopicZTPool` / `getTopicZBPool` / `getTopicDTPool`（无涨停原因，题材归因降级） |
| 连板数 | 同花顺 `continuous_limit_up` 天梯 | 东财池自带；都没有时按「N 天 N 板」推断 |
| 题材榜 | 同花顺 `block_top`（含连续上榜天数） | 无（只用涨停原因聚类） |
| 昨日涨停今日表现 / 强势股 / 次新 | 东财 `getYesterdayZTPool` / `getTopicQSPool` / `getTopicCXPooll` | 无（对应指标留空） |
| 人气榜 | `DataFetcherManager.get_hot_stocks`（东财人气榜 → 飙升榜 → 雪球） | 无（F 维度降级） |
| 日 K | `chart_service.get_kline`（同花顺行情） | 无（反包形态标「未经确认」） |
| 题材新闻 | `NewsSearchService.search_all`（财联社 / 同花顺 / 东财等，无需 key） | 无（故事空间按规则估计） |

- 同花顺池接口**不带连板数**，`high_days`「21天12板」是 N 天内 M 次涨停，不一定连续；连板数只能从天梯拿。
- 同花顺首封 / 末封时间是 epoch **秒**字符串；东财是 `92500` 这样的整数，价格单位是**厘**。
- 东财 `getYesterdayZTPool?date=X` 返回的是「X 的上一交易日涨停股在 X 当天的表现」。
- 两边口径不同：东财含北交所（92xxxx）与 ST，统一先过滤再计数。
- 东财炸板 / 跌停池只保留约 30 个交易日，所以池子按日落库（`daban_pool_rows`）。
- 上游可能返回 HTTP 200 + 截断 body，解析失败当上游异常处理，不当空池。
- 盘中生成标 `intraday`：周期结论是临时的，雷达不拿它当前一交易日的周期；收盘后再生成一次会覆盖。

## 生成为什么走后台任务

一次生成要打十几个上游、拉最多 40 只候选的日 K、搜 4 个题材的新闻，再调一次模型，实测 30–80 秒；首次生成还会按日回补近 20 个交易日的周期指标（不调模型）。这超过前端 30 秒的 HTTP 超时，所以与行业资金一样：`POST /jobs` 提交、`GET /jobs/{id}` 轮询，结果落库后由 `GET /overview` 只读返回。两次生成之间有冷却（`DABAN_REFRESH_COOLDOWN_SEC`）。

## 配置

全部有默认值，不配置也能用。说明见 `.env.example` 的「我是打板王」段：`DABAN_ENABLED`、`DABAN_REFRESH_COOLDOWN_SEC`、`DABAN_LLM_TIMEOUT_SEC`、`DABAN_REASONING_EFFORT`、`DABAN_INCLUDE_BSE`、`DABAN_RULES_FILE`、`DABAN_RETENTION_DAYS`、`DABAN_PUSH_ENABLED`、`DABAN_AUTO_GENERATE`、`DABAN_AUTO_PUSH`、`DABAN_LIVE_ENABLED`、`DABAN_LIVE_CACHE_TTL_SEC`、`DABAN_LIVE_POLL_SEC`、`DABAN_LIVE_PUSH_ENABLED`。`DABAN_MAX_ACTIONABLE` 已停用（推荐不设数量上限），保留只为兼容旧配置。

`DABAN_RULES_FILE` 指向一个 YAML，只写想改的键，与内置默认值深合并（列表整体替换），例如：

```yaml
stage:
  ice: {zt_max: 35}
rec_score:
  threshold: 0
overrides:
  index_rise: {sh000001: 1.0}
worldview:
  commonality_same_min: 0.6
```

可调的规则组：`stage`（周期阈值）、`rec_score`（计分表、门槛、距涨停）、`worldview`（边界、节点放行、共性阈值）、`overrides`（推翻信号阈值）、`surge_point`（大盘急拉推荐点）、`expectation`（预期基准）、`preboard`（候选与热点题材门槛）、`market_scan`（全市场扫描）、`feature_book`（日 K 取数）、`realtime_gate`（实时周期重判）、`radar_log`（留档间隔）。

**让它在周一自己跑起来**：在 `.env` 设 `DABAN_AUTO_GENERATE=true`，然后重启服务（`--serve` / `--serve-only` / 桌面端）。交易时段后台每 30 秒轮询一次雷达（评分、记「重点」、留档、回填成绩），交易日 15:30 后每 10 分钟检查一次、当天还没有收盘后的复盘就生成一次（世界观、观察清单、「重点」收盘对账）。服务启动时先检查一次；开盘前（09:00 之前）和非交易日也每 10 分钟检查一次：上一个交易日收盘后没生成过（服务当时没开、生成失败，或只在盘中生成过），就补生成那一天，开盘时世界观和次日观察清单才有；交易时段内不补，题材榜、人气榜只有「当下」，补出来的不是那天收盘的样子。不需要 `SCHEDULE_ENABLED`（后者会顺带启用每日个股分析与通知）。`GET /api/v1/system/scheduler/status` 的 `background_tasks` 列出当前注册的后台任务。
