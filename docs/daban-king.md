# 我是打板王（短线情绪周期与打板推荐）

「我是打板王」把 `92科比` 与 `陈小群` 两位游资公开分享的短线理念做成每日盘后复盘：先判定情绪周期，再过连板梯队与主线题材，然后**两派各出一条推荐线**，最后用一组透明投票裁决「今天更适合哪种打法」。每条推荐理由都挂着理念条目的出处，悬停可看原文摘句。摘句全部是两篇原文的原话（`tests/test_daban_principles.py` 在本地有原文时逐字核对），原文没有说过的判断不挂出处，只作为「系统补充信息」放在卡片的事实区。

> 这是规则化的复盘工具，不是荐股系统。两篇原文的观点只代表作者个人，陈小群那篇还是第三方整理稿；页面与推送都会附免责声明。

## 设计原则（都来自原文）

1. **周期先于个股**。两人都把情绪周期放在第一位：周期决定能不能做、做什么模式、仓位上限，之后才轮到选股。某一派判定空仓时那条线就明确显示空仓，这是该派理念本身的要求。
2. **预判 + 验证**。科比强调「先于市场发现可发酵的舆论事件」，陈小群强调「预判必须经市场验证才执行」。盘后用规则挑出候选，每张卡片同时给出**次日触发条件**与**放弃条件**，不满足就不买。
3. **规则打分，模型只做原文说无法量化的部分**。科比原话：「量价图形……很难量化」「这个故事能讲多大」。所以周期、角色、模式、门控、评分全部是确定性规则；模型只评题材的故事空间、写理由，调分被截断在 ±10。
4. **两派冲突不调和，而是分线**。退潮期陈小群「坚决空仓」，科比「主跌第二天尾盘找买点、第三天必修复」。两条线各按自己的门控矩阵出推荐，裁决只给倾向，不替用户删掉另一派。

## 页面结构

页面顺序就是两人的复盘顺序（科比 #38：先把当天涨停过一遍，再看昨日涨停溢价，再挖首板新闻；陈小群：周期定位 → 主线识别 → 龙头确认 → 信号等待）：

1. **情绪周期**：陈小群六阶段 + 科比四阶段视角、八个指标卡（较昨日变化，涨红跌绿且带正负号）、近 10 个交易日的阶段条带（点击回看）、可展开的六阶段条件核对表。
2. **连板梯队**：从最高板往下排，层间标分层晋级率（1进2、2进3…），每只显示角色、板型、首封时间、炸板次数、封单/流通市值与涨停原因。
3. **主线题材**：题材排名、涨停数、最高板、持续天数、状态（启动 / 主升 / 高位分歧 / 退潮）、新老题材、故事空间（模型评估，模型不可用时标「规则估计」）、近 3 日新闻。
4. **今日打法裁决**：9 张投票逐票显示命中与否和依据；模型若不同意，单独显示「模型补充意见」，不改裁决。
5. **两条推荐线**：被裁决推荐的一线排前面。每张卡片含打板王指数与评级、模式、角色、行动级别（可执行 / 试错 / 观察）、建议仓位、理由（只挂本派条目）、次日触发 / 放弃条件、七维得分明细。两条线都推荐的票标「两派共识」。
6. **昨日推荐 → 次日表现**：按打法分别统计，喂给裁决里的「近期战绩」票（科比 #22：不断修正自己）。
7. **排除名单**：中位股、跟风、死亡换手、孤立弱板、一字板……每只写明原因与出处。

## 情绪周期

### 指标（统计口径：沪深主板 + 创业板 + 科创板，剔除 ST；北交所默认不含）

| 指标 | 口径 |
| --- | --- |
| 涨停家数 | 收盘封住涨停 |
| 连板支数 / 连板高度 | 连板数 ≥2 的股票数 / 当日最高连板数（来自同花顺连板天梯） |
| 连板晋级率 | 今日连板数 / 昨日涨停数；分层晋级率按昨日板数分组 |
| 昨日涨停今日表现 | 昨日涨停股今日等权平均涨跌幅与上涨占比（东财 `getYesterdayZTPool`） |
| 大面股 | 昨日涨停今日跌幅 ≤ -5% |
| 炸板率 | 炸板 / (涨停 + 炸板) |
| 龙头封单比 | 最高板封单金额 / 流通市值 |
| 主线集中度 | 第一题材涨停数 / 总涨停数（原文「跟风率」没给口径，这是本功能的解释） |

### 六阶段判定（透明投票）

| 阶段 | 条件（默认阈值） | 陈小群仓位上限 |
| --- | --- | --- |
| 冰点 | 涨停 <30；连板 <5 支；昨日涨停今日 ≤ -2% | 0 |
| 回暖 | 涨停 30–50；连板 5–8 支；晋级率较昨日上升 | 10–20% |
| 发酵 | 涨停 50–80；连板 8–12 支；主线集中度 >30% | 30–50% |
| 高潮 | 涨停 >80；高度 ≥5 板；龙头封单比 ≥3% | 50–80% |
| 分歧 | 涨停较昨日减少；高度回落；大面股增多 | ≤30%，只卖不买 |
| 退潮 | 跌停 >10；连板 <3 支；昨日涨停今日 ≤ -3% | 0 |

- 命中率最高者胜；数据缺失的条件按未命中计。平局时取与昨日阶段相邻的，没有昨日阶段时取更保守的（先认亏钱阶段）。
- 最高命中率 < 2/3 时标「过渡态」。
- 跌停 > 20 家直接判退潮（陈小群：>20 家明确退潮）。
- 科比四阶段由六阶段映射（冰点 / 回暖 → 低位震荡，发酵 / 高潮 → 主升，分歧 → 高位震荡，退潮 → 主跌），主跌再按「连续杀跌第 N 天」细分（杀跌日 = 退潮或冰点且昨日涨停溢价为负）。

**阈值要人工校准**：陈小群那篇是第三方整理稿，数字对应的是约 4000 只股票的年代（现在约 5400 只）。全部阈值都可以用 `DABAN_RULES_FILE` 覆盖。

## 主线题材与个股角色

- **归因**：同花顺涨停池每只股票带「涨停原因」（如 `PCB+AI服务器+HDI板`），按 `+` 切成标签，剔掉业绩、订单、增持这类公司自身催化，再按「互相包含」合并：两两标签的公共后缀（≥3 字，如「人形机器人 / 工业机器人」→「机器人」）作为核心词把它们并到一起。同义但字面不沾的合并留给模型。
- **主线**：按 `涨停数 + 2×连板数 + 最高板` 排名，前 3 且涨停 ≥3 只为主线。
- **持续天数**：取同花顺题材榜的连续上榜天数，与本地历史「每天至少 2 只涨停」的连续天数取大。
- **新 / 老题材**：与近 10 个交易日的主线比较：同名为老题材，字面相关为共性发散，都不沾为新题材（科比：补涨是共性发散，切换必须完全不同）。
- **角色**：总龙头（全市场最高板，并列时依次比 N 天 M 板里的 M、首封时间、人气榜）、板块龙头、前排（2 板或首封最早的 3 只首板）、低位补涨（低价小盘）、**中位股**（3 板到最高板 − 1，排除，科比 #12）、**跟风**（主线里非前排且不够低价小盘，排除，陈小群「只做龙头不做杂毛」）。

## 七种战法与两派门控

| 模式 | 识别 | 出处 |
| --- | --- | --- |
| M1 龙头·分歧介入 | 总龙头 / 板块龙头；一字或缩量秒板标「等分歧」；昨日最高标今日首阴 / 断板也进来（龙头低吸） | 科比 #9 #17 #26；陈小群 四.2 四.3 |
| M2 弱转强 | 炸板回封、尾盘板（末封 ≥14:30）；或主线高标今日大跌。必须属主线、换手 ≤70% | 陈小群 四.1；科比 #32–#36 |
| M3 低位补涨 | 主线里的低价小盘首板 / 2 板 | 科比 #5 #24 #27 #30 |
| M4 一进二 | 主线或新题材的换手首板，次日打二板（原文只有定位，没有选股标准，见下文「首板回测」） | 科比 #12；陈小群 回暖期 |
| M5 反包 | 反包首板（近 20 日有 ≥3 连板、断板后今日重新涨停，用日 K 确认）；或 3 连板以上首阴 | 科比 #18；陈小群 四.4 |
| M6 高低切 / 切换 | 高位见顶或主跌之后，新题材的低位股 | 科比 #7 #8 #14 |
| M7 次新 | 东财次新池里开板后走强的票 | 科比 #19 #24 |

每个候选进哪条线、以什么级别进，由该派自己的门控矩阵决定（默认值见 `src/services/daban/constants.py`，可覆盖）。几个关键差异：

- 陈小群线：每一格都对应原文阶段表的「操作要点」，没写到的不放行。冰点只观察新题材萌芽；回暖期才做首板 / 二板，而且只做**新题材**（老题材降为观察）；发酵期「围绕龙头或换手龙介入，分歧转一致时加仓」（龙头、弱转强可执行，首板只观察）；高潮期「坚定锁仓龙头」（只有龙头可执行）；分歧期只放行**全市场绝对龙头**的低吸与「大势未死」时的二波反包；退潮空仓。原文「只做龙头不做杂毛」，低位补涨（M3）不做；原文没有次新打法，M7 不放行。
- 科比线：主跌第 1 天只观察，第 2 天龙头尾盘试错、切换与次新试错，第 3 天起等修复；高位震荡轻仓、不博穿越；主升段「分歧时介入」。科比原文没有仓位数字，线仓位上限（低位 ≤20%、高位震荡 ≤30%、主跌第 2 天 ≤10%）是本功能对「轻仓 / 试错」的量化解释。
- 「可执行」每条线最多 4 只（科比：分四个票）；单票仓位陈小群线龙头 ≤30%、跟风 ≤10%，科比线每票 ≤25%，合计不超过线仓位上限。
- 某派的理念里找不到支撑一只票的理由（没有本派条目可挂），这只票就不进这条线。

## 打板王指数（0–100）

`A–G 七维规则分（满分 100）+ 模型调分（±10）− 风险扣分（≤20）`。周期适配不进分数，所以同一只票在两条线里分数相同、行动级别可以不同。

| 维度 | 满分 | 口径 |
| --- | --- | --- |
| A 题材地位 | 25 | 主线排名 + 题材生命周期（持续超 30 天减分） |
| B 个股地位 | 20 | 总龙头 20 / 板块龙头 16 / 前排 10 / 补涨 8 |
| C 位置 | 15 | 绝对高位（龙头）或绝对低位（1–2 板） |
| D 板质量与形态 | 15 | 换手板 > T 字板 > 一字板；尾盘板减分（科比 #33 算弱板，弱转强模式除外）；封单比；换手 5–30%；分歧中回封 |
| E 股性 | 10 | 同花顺历史封板率 + 近半年涨停次日平均溢价（日 K 反推） |
| F 人气与流动性 | 10 | 东财人气榜排名、成交额、换手 |
| G 低价小盘 | 5 | 股价与流通市值分档 |

风险扣分：题材持续超 45 天、题材内昨日涨停今日亏钱、高位放量滞涨、死亡换手。评级：≥85 S、75–84 A、65–74 B；低于 65 只进观察。

## 模型只写理由，不打分

模型一次调用完成：故事空间与共性说明、每只候选 ±10 调分（必须写理由）、两条线各一段解读、对裁决的补充意见、风险提示。约束：

- 只能提及候选清单里的代码，越界代码（包括自由文本里的 6 位数字）被抹掉并记入 `dropped_mentions`；
- 只能引用理念条目库里的 id，陈小群线只能挂 C 条目、科比线只能挂 K 条目；
- 调分截断到 ±10；模型对裁决的不同意见只展示，不改裁决；
- 新闻标题用 `BEGIN/END_UNTRUSTED_NEWS_ITEMS` 包裹，当作不可信文本；
- 模型不可用、超时、返回空或无法解析时退回规则化解读（调分为 0，故事空间按新闻条数与涨停规模估计），页面标「规则兜底」。

输出预算是 16384 token：deepseek-v4.1-flash 即便 `reasoning_effort=low` 也会先吃掉 5k–8k reasoning token，8192 下正文会为空或被截成半截 JSON（与消息面汇总踩过的坑相同）。

## 首板回测（`scripts/daban_backtest.py`）

两篇原文对首板只有定位：科比「低位就是做首板或者一进二」（#12）、「根据新闻去挖掘一些票」（#38），陈小群回暖期「聚焦新题材首板/二板」。没有任何量化标准，所以在定首板规则之前先用历史数据回放。

```bash
python scripts/daban_backtest.py                               # 同花顺可回溯的全部区间（约一年）
python scripts/daban_backtest.py --start 2026-04-01 --end 2026-10-20
```

数据缓存在 `data/daban_backtest/`（不入库），报告写到 `data/daban_backtest/report/report.md`。周期、题材、角色直接复用线上模块，与页面口径一致。三种买法：

- **首板打板**：盘中第一次触板以涨停价买入，**不论最后封没封住**（只看封住的首板是幸存者偏差）。环境特征取前一交易日收盘。
- **一进二**：首板次日盘中触板、且不是一字（买得到）时以涨停价买入；首板当天的特征与次日开盘幅度都是买前已知。
- **炸板次日**：炸板当天收盘买入，用来检验「从炸板股里预判明天首板」。

卖出：当天涨停多拿一天（科比 #23），否则卖（#25），同时给开盘卖与收盘卖两个价。收益是理论成交，未计费用、滑点，也没有模拟排板买不到。

2025-10-09 ~ 2026-10-20（250 个交易日）的主要结论：

| 买法 | 样本 | 结果（次日开盘卖） |
| --- | --- | --- |
| 首板打板 | 18263 次触板 | 封住率 72%；均值 +0.67%、胜率 46%。封住 +2.65%，炸板 −4.40%，盈亏几乎全由「封不封得住」决定 |
| 一进二 | 13519 只首板，可买 21% | 均值 −0.31%、胜率 40%（收盘卖 −0.91%）。没有任何特征分组显著为正 |
| 炸板次日 | 6229 只 | 次日涨停 7.8%；收盘卖均值 −0.54%，几乎所有分组为负 |

- 与原文一致：首板打板在「主跌第 2 天」均值 +1.95%（316 例，前后半段都为正），「主跌第 1 天」−0.08%，对应科比 #9；一进二次日高开 ≥9%（含一字）−1.32%，对应 #35「一字板对接力不友好」；尾盘首板做一进二 −2.09%；股价 ≥40 元的一进二 −0.91%，低价（<10 元）为正，对应 #27「低价为王」。
- 与直觉不一致：一进二里「新题材」−0.79%（t = −3.1），「老题材」+0.19%；陈小群「回暖期聚焦新题材首板/二板」在回暖期样本只有 154 例，前后半段方向相反，数据不足以支持或否定。
- 盘中可知的题材信息（历史涨停原因是否命中昨日主线）对首板打板几乎没有区分度；收盘后的题材聚类区分度很高，但那是前视信息，不能用来定盘中规则。

因此当前版本**没有**加入「首板预判」模式：基于炸板股的预判在数据里是负收益；科比原文的预判是「先于市场发现可发酵的舆论事件」，依赖新闻，现有历史数据无法回测。

## 盘中首板雷达（`/daban-king?tab=live`）

目标：开盘后按两派打法找出当天值得打的首板，吃第二天的溢价。页面在交易时段默认打开这个标签，每 10 秒自动刷新（后端缓存 5 秒），不需要手动点。

### 门控只用「前一交易日收盘」的周期

门控**锚定涨停池所属交易日的前一个交易日**：库里有那一天的复盘（完整复盘或冷启动回补）就用它，没有就用最近 3 个交易日的涨停 / 炸板 / 跌停池现算（不调模型，约 5 秒，缓存 10 分钟）。**不会**拿更早某天的复盘来门控今天——忘了生成复盘也不会用错周期。盘前 / 非交易日打开页面时，显示的是上一交易日的盘中结果回看，门控相应用它的前一交易日，页面会标注。

盘中雷达的「今日门控」卡要能自解释「今天为什么不出手」，不用翻被挡列表里的某一只票，所以把判定过程摆在卡上：

- **每派一行原话**：放行的阶段给该派原文依据（如科比主跌第二天「尾盘就可以找买点」、陈小群回暖期「聚焦新题材首板/二板，轻仓试错」），关闭的阶段给「此阶段不打首板」的理由，都带条目出处；科比线额外标「连续杀跌第 N 天」。
- **判定依据块**：阶段标签 + 条件命中率 + 该阶段三个条件的实际值与阈值（命中 / 未命中 / 数据缺失逐条标记），命中率为 0 时标「按涨停家数兜底分档」，被硬规则改判时直接显示改判原因（如「跌停 49 家 > 20，直接判退潮」）。
- **前一交易日五大指标**：涨停、连板、跌停、最高板、晋级率、昨日涨停今日溢价、大面数——与盘后复盘同一份 `metrics`，口径一致。

| --- | --- | --- |
| 92科比 | 回测：主跌第 2 天打首板 +1.95%（316 例，前后半段都为正），主跌第 1 天约 0 且前后半段都差；原文「第一天杀跌是很恐怖的」 | 低位震荡 / 主升 / 高位震荡 / 主跌第 3 天起：试错；主跌第 2 天：可执行；主跌第 1 天：不做 |

### 降为观察的情况（只用买入那一刻能看到的信息）

- 开盘一分钟内首次触板：多为一字 / 秒板，买不到，回测 -0.72%
- 一字板：盘中没有买入机会
- 14:30 之后才首次触板：科比把尾盘偷鸡板算弱板（#33）。只看**首次**触板时间——10:00 触板、14:50 回封的票，买点在 10:00，不会被事后降级
- 陈小群线：不是新题材（与近 10 个交易日的主线比），或同题材此前触板不足 2 只

### 盘中实时门控：前一交易日只做底线

只用前一交易日收盘的周期门控，等于把「昨天的状态」当成「今天的状态」——这本身就是一次预判，正好是陈小群「市场永远是对的，预判必须得到市场验证才执行交易」的反面。2026-10-23 就吃过这个亏：10-22 收盘 49 家跌停被判退潮，10-23 两派全天不出手，而当天实际涨停 80 家、昨日涨停今日溢价 +3.38%，13:00 后一小时内从 26 只封板冲到 55 只，雷达一条推荐都没给。

所以盘中按**今天的 tape** 实时重判，前一交易日的周期退为底线：

- **升级（赚钱效应恢复）**：昨日涨停今日溢价转正（科比 #28「看昨日涨停股今日表现」、陈小群五大指标之一）、当日涨停数不低于昨日收盘、炸板率不高于 `zab_rate_max`。满足后按今天的周期查门控表，**只在更放行的方向生效**，两派同时适用——盘中转强要能跟上节奏，不能让用户被昨天的数据钉死。
- **降级（资金撤了）**：溢价转负是必要条件，再叠加「炸板率抬升 / 跌停多于昨日 / 涨停数从当日峰值回落 `peak_drawdown`」中任意一条。**只要还有热点题材在最近 `theme_accel_window_min` 分钟内新增封板 ≥`theme_accel_min` 只就不降级**——那是资金在换题材而不是在撤（科比讲的「切换」），正好不该错过轮动那一波。降级只**停发新名额**，已锁定的不动：A 股 T+1 撤不回来，成绩单也必须记当时真实给出的票。
- **防抖与样本量**：升降级都要连续 `confirm_rounds` 轮满足；当日涨停数不到 `min_zt_sample` 一律不重判（09:35 只有几只涨停时，和昨天比什么都不可靠）。
- **仓位**：升级后给升级后阶段的完整仓位上限，不按剩余时间打折（T+1 下上午没用掉的仓位本来就空着），名额总数仍受「分四个票」限制。

门控表的键一律按「**今日**是主跌第几天」理解：科比原话「第一天杀跌是很恐怖的，但是**第二天**的杀跌如果还是持续的话，**尾盘**就可以找买点」说的是当天，回测里「主跌第 2 天 +1.95%」也标在买入当天。所以盘前用前一交易日的天数 +1 做估计（昨天第 1 天 → 今天按第 2 天门控），盘中由实时重判按今天的 tape 纠正；第 2 天的「可执行」只在 `fall2_late_time`（默认 14:00）之后放行，之前按试错对待。

参数都在 `rules["realtime_gate"]`，可用 `DABAN_RULES_FILE` 覆盖；`enabled=false` 即退回「只看前一交易日」的旧行为。

### 集合竞价不算数

09:15–09:30 期间上游不给首次封板时间，竞价封单也可以撤，所以**竞价期间一律不占名额**，只在名单里标「先观察，等 9:30 后再判断」。首次封板时间缺失的记录即使被写进了库（早期版本的 bug），读取时也会被忽略，不占名额。9:30 之后第一分钟内触板的按「开盘即封」降为观察。

### 未涨停候选：先给「买得进」的票

只报告已经封板的票没有意义——看到时已经买不进去了。所以雷达额外给出一组**还没涨停、但正在快速拉升**的候选，放在每派的「未锁定潜力股」标签里（按发现时间倒序，最新的在最上面），标「未涨停 · 还差 X%」，并给出封板价、量比、题材内今日已涨停几只。

- **怎么找**：东财盘口异动「火箭发射 / 快速反弹」（实测约 4 秒延迟）给出正在拉升的股票 → 腾讯快照补现价、涨停价、量比、换手 → 门槛是当日涨幅 ≥3%、距涨停价 ≤6%、流通市值 ≤500 亿、非 ST、不在涨停池 / 炸板池 / 昨日涨停里。
- **上游不稳时怎么办**：东财 `push2ex` 在 09:30 开盘后几分钟会读超时或直接断连（实测 2026-10-23 09:30–09:32 连续多轮，`Read timed out` 与 `RemoteDisconnected` 各半）。所以这一路：两类异动**并发取、共用预算**，单次超时 `fetch_timeout_sec`（默认 4 秒，不占满 15 秒总预算），整路最长 5 秒返回；取数失败时**沿用 `reuse_sec`（默认 90 秒）内的上一次成功结果**，候选本来只看「最近 10 分钟的异动」，复用不改变语义，但一轮失败不会把候选清空，页面会标「沿用 N 秒前的一份」。两类异动互不影响，一路挂了另一路照常。
- **怎么算热点**（三道门槛，缺一不可，卡片上都写出来）：
  1. **够热**：板块当日涨停 ≥3 只（与盘后「主线」口径一致），或占全市场涨停 ≥5%；
  2. **在升温**：板块连续上榜 ≥2 天，或当日涨停数比前一日多——只爆发一天的散点不算发酵；
  3. **有新闻催化**：板块名近 3 日相关新闻 ≥3 条（走项目已有的新闻搜索，财联社 / 同花顺 / 东财等）。
     新闻查询在后台异步补缓存，第一轮可能显示「新闻校验中」，下一轮生效；新闻服务整体不可用时降级放行并标注。
- **怎么贴到板块**：板名和标签都先去掉「概念 / 板块 / 产业链」后缀再比（「人形机器人」才能对上「机器人概念」）。
  候选股先用近 90 天历史涨停原因贴，贴不上再用**东财选股器的所属概念**兜底（批量查询、按日缓存），
  卡片标注「按所属概念」。两样都没有就不进候选。
- **怎么对应战法**：仍按前一交易日的周期门控。科比线在放行的阶段全部接受；陈小群线要求新题材、且题材内已有 ≥2 只涨停（资金合力）。
- **怎么用**：这些候选**就是锁定名额的来源**（见下节）。卡片写明「封板价 X——封住时才谈打板；不封就不要追」。
- **向前验证**：未涨停候选同样留档（`origin=preboard`），收盘时记录它最终有没有封板，成绩单里单独给「候选封板率」，不与真实交易混在一起。

局限要说清楚：回测只覆盖了「触板之后」的样本，**没有**「未涨停→拉升」这一类候选的历史验证，所以这里只给事实和触发价，不做胜率承诺。

### 题材从哪来

卡片必须能看出「为什么符合战法」，所以题材按四级来源解析，并在卡片上标注来源：

1. **当日涨停原因**（同花顺 `reason_type`）——最准，但新封板后要几秒到一分钟才出现，竞价期间完全没有；
2. **历史涨停原因**（本地近 90 天涨停池）——这只票最近因为什么涨停；
3. **当日题材榜板块归属**（同花顺 `block_top` 的成员，缓存 20 秒）——「现在哪些板块在涨停」，最贴近当下热点；
4. **所属概念**（东财选股器，批量查、按日缓存）——前三级都空时的兜底，卡片标「按所属概念」。

第四级主要是为**炸板股**准备的：同花顺炸板池不返回 `reason_type`（实测当日 100% 为空），这些票既没有当日原因，也常常没有近 90 天涨停记录。概念列表很宽（一只票挂 30 多个很常见），整份拿来当题材等于随便挂一个，所以只取**与当日题材 / 题材榜相交**的那部分，并取其中最热的一个——「它的概念里正好有一个今天在涨停的题材」才算师出有名。局限要说清楚：取的是最热的交集，不一定是这只票最具代表性的那个概念。

**四级都挂不上的票直接从名单里剔除**，不再显示「题材待公布」混在「未锁定潜力股」里：科比要「有逻辑的低位首板」、陈小群要「新题材 + 资金合力」，两派都不打师出无名的票。被剔除的票收进「今日不允许的涨停股」，注明「师出无名」，保留可审计性。

唯一的例外是**兜底本身不可用**：概念接口整批没有返回时按「这一级没查过」处理，照旧保留在名单里并显示「题材待公布」——上游故障不应该静默清空名单。

### 今日主线：先定方向，再看票

候选太多太乱会让人没法下手，所以页面在「刚刚发生」下面给一组「今日主线题材」卡片——和盘后复盘的「主线识别」同一套口径（够热 + 在升温 + 有新闻催化）。卡片**按热度排序**，颜色从红（最热）渐变到蓝（最冷），显示排名、当日涨停数、连续上榜天数、新闻条数，以及**按派分开**的锁定名额与候选数（`名额 陈 1/4 · 科 4/4`、`候选 陈 0 · 科 7`）。**点击即筛选**：只显示该题材下的已锁定与未锁定候选，默认「全部题材」。

名额与候选之所以必须分派显示：两派名额互不相通（见下），把两派加在一起会让一个题材看起来早就满了。「全部题材」上的候选数是两派各自的未锁定总数，**会大于各题材候选数之和**——贴不上任何热点题材的票只在「全部题材」里出现。

**题材归属按 `theme_key` 对齐**：题材卡片的 key 来自同花顺题材榜（「机器人概念」），而已涨停 / 炸板票的题材名来自涨停原因聚类（「人形机器人」，`normalize_tag` 会去掉「概念 / 板块 / 产业链」后缀）。后端按归一化名 + 互相包含把每只票落到一个热点题材的 key 上，筛选、名额统计与候选计数一律用这个 key；按展示名直接比字符串会让整列筛空。贴不上的票 `theme_key` 为空串，不占题材名额。

**锁定名额按题材热度分配**：热度前 3 名的题材各 4 个名额，其余题材各 2 个（`quota_top_n` / `quota_top` / `quota_other` 可配）。**这个名额是每派各自的**：「机器人概念 4 个名额」= 陈小群 4 个、科比 4 个，不是两派合起来 4 个。盘中新题材挤进前 3 名时，名额自动变成 4 个；掉出前 3 名时已锁定的名额不会收回，只是不再新增。

名额上一共有三道约束，**取最严的那个**：

1. **每派名额总数** `DABAN_MAX_ACTIONABLE`（默认 4，科比「我一般是分四个票操作」）——这是分仓纪律，不靠仓位上限间接实现；
2. **单题材单派的占用上限**（上面的 4 / 2）——防止 4 个名额全压在一个冷题材上；
3. **该派当前阶段的总仓位上限**（`live_caps`）。

所以热度前 3 名的「4 个名额」实际含义是「一个够热的题材最多可以占满本派全部名额」，冷题材最多占一半。

### 锁定 = 此刻还能买

名额只发给**还没涨停、正在拉升、距涨停很近**的候选；已经封板或炸板的票不占名额——它们出现时已经买不进去了，只作对照（卡片注明「已经封板，承接不到」）。这解决了「名单上全是已封板、根本没法出手」的问题。

排序：距涨停越近越优先，同距按量比。每派最多 `DABAN_MAX_ACTIONABLE`（默认 4，科比「分四个票」）只，合计不超过该派当前阶段仓位上限。

### 名额：先到先得，炸板也占名额

按首次触板时间分配，每派最多 `DABAN_MAX_ACTIONABLE`（默认 4，科比「分四个票」）只，且合计不超过该派当前阶段的仓位上限（`live_caps`；陈小群回暖期 20%，科比高位震荡 30%、主跌第二天之后 25% 等，科比各阶段数字是对「轻仓 / 试错」的量化，可用 `DABAN_RULES_FILE` 覆盖）。首板不是龙头，单票仓位：陈小群线按「跟风不超过 10%」，科比线按「分四个票」。用满后的票只给观察。

**名额一旦给出当天锁定**（锁定时的现价记进 `seen_price`，回填收益也按这个价算，而不是事后才有的打板价）：每次刷新先读出当天已锁定的名额（盘中留档 + 收盘补录），原样保留动作、仓位与名额序号，只把剩下的名额和剩余仓位分给新出现的票。理由：A 股 T+1，上午用掉的仓位当天腾不出来；成绩单也必须记当时真实给出的票，允许中途换票等于只留赚的。因此：

- 数据晚到、但首次触板更早的票，不会把已锁定的挤掉，只进观察并注明「数据晚到」；
- 已锁定的票后来不再符合条件（比如题材聚类变化），名额照旧；在这一轮数据里缺失的，也照留档显示「本轮未返回」；
- 名额用满后出现的新题材 / 新票只进观察，用户可自行判断；它们次日会进入一进二候选与首板预判跟踪。

读已锁定名额、分配、留档在同一把进程锁里完成，避免页面轮询和后台任务同时把一个空名额分给两只票；数据库层再按「打法 + 名额序号」去重兜底。

**触板后炸开的首板照样占名额、照样留档**：那一刻已经按打板价买了，名单里只留封住的就是幸存者偏差（回测炸板占触板 28%，平均 -4.40%）。卡片会标「已炸板」，每派列出自己的卖出纪律（科比：次日不涨停就走、与预期不符坚决止损；陈小群：5% 止损）。

### 为什么盘中不打分

回测把「封板那一刻已经知道的信息」逐项检验过：同题材同伴数（0 / 1–2 / 3–5 / ≥6 只）次日开盘卖收益都在 +0.5% ~ +0.8%，t 值互相重叠；这只票历史涨停原因是否命中昨日主线同样没有区分度。而封住 vs 炸板是 +2.65% vs -4.40%，买入那一刻无从判断。所以雷达只给**行动级别 + 可核对的事实**（首封时间、开板次数、封单金额与封单比、同题材同伴数、涨停原因、流通市值、换手），排序按首封时间，不按任何"预测分"。

早期版本曾用「收盘后的题材聚类」判断主线，回测显示区分度很高——但那是前视信息（只有封住的股票才有涨停原因），盘中不可用，已废弃。

### 留档、推送与成绩单

- **每派两个标签**：「已锁定」是拿到名额的票（动作、仓位、名额序号锁定，显示锁定时刻）；「未锁定潜力股」是通过本派门控但没拿到名额的票（名额满、数据晚到、刚发现还没轮到），**按发现时间倒序**，最新的在最上面，盘中实时新增。标签上的条数与题材卡片上的候选数同源同判据（有没有拿到名额），所以点某个题材时两个数一定对得上。
- **盘中第一次给出「可执行 / 试错」就留档**（`daban_live_hits`，`origin=live`），之后不改动作、仓位与首次出现时刻——那是用户当时看到并可能下单的东西。
- **收盘复盘按同一口径补录**盘中没记到的（`origin=close`，比如那天没开页面），并写入是否封到收盘。补录不依赖前一天是否生成过复盘。
- 次一交易日收盘后自动回填次日开盘 / 收盘相对打板价的收益（雷达轮询时 10 分钟最多回填一次，收盘复盘也会回填），页面「盘中雷达成绩单」按打法展示封住率、收益和胜率。盘中刷新复盘不会回填任何东西。
- **推送**（`DABAN_LIVE_PUSH_ENABLED=true`）：新出现「可执行 / 试错」时推到已配置的通知渠道，内容含打板价、名额、仓位、题材事实、原文出处与卖出纪律，按「交易日 + 打法 + 代码」去重。开启后若同时 `SCHEDULE_ENABLED=true`，交易时段每 30 秒后台轮询一次（Scheduler 主循环的下限），不开页面也会留档和推送。
- 首板预判（科比「先于市场发现可发酵的舆论事件」）**只做向前验证**：每天收盘记录候选（今日炸板且属于发酵中主线、或近 60 天在该题材涨停 ≥2 次），下一交易日回填是否触板 / 封板，结果在复盘页「首板预判跟踪」里。不做推荐，因为依赖新闻的预判没有历史语料可回测，而可回测的替代口径（炸板股次日）一年 6229 例为 -0.54%。

### 实时数据源

| 数据 | 来源 | 实测 |
| --- | --- | --- |
| 当前涨停股（含涨停原因） | 同花顺 `dataapi/limit_up/limit_up_pool` | 页面自身每 5–30 秒刷新；返回带 `trade_status` 与日期，非当日会标 `stale` |
| 连板数 | 同花顺 `continuous_limit_up` | 约 0.2s |
| 炸板股 | 同花顺 `open_limit_pool` | 约 0.2s |
| 封板 / 回封 / 炸板事件流 | 同花顺 `dataapi/limit_up/change` | 当天 393 条，从 09:25:00 起，精确到秒 |
| 是否真封住（现价 = 涨停价且卖一为空） | 腾讯 `qt.gtimg.cn` 批量行情 | 52 只约 0.5s；收盘时判出 51 只，与同花顺 52 只一致 |

盘中单次快照实测约 1.4 秒（含 4 个上游）。东财 `push2.eastmoney.com` 全市场行情在本机网络被重置，未采用；东财盘口异动 `getAllStockChanges` 可用，作为备用信号源已在适配器里。

**已知局限**：盘中延迟（从真实封板到接口可见）还没实测，探测脚本见 PR 说明；打板经常排不上强势板，炸板的却一定买得到，真实成交会差于回测口径。

## 数据源与已知陷阱

| 数据 | 主源 | 兜底 |
| --- | --- | --- |
| 涨停 / 炸板 / 跌停池 | 同花顺 `data.10jqka.com.cn/dataapi/limit_up/{limit_up_pool,open_limit_pool,lower_limit_pool}`（无 token，支持历史日期，带涨停原因、N 天 M 板、封板率） | 东财 `push2ex` `getTopicZTPool` / `getTopicZBPool` / `getTopicDTPool`（无涨停原因，题材归因降级） |
| 连板数 | 同花顺 `continuous_limit_up` 天梯 | 东财池自带；都没有时按「N 天 N 板」推断 |
| 题材榜 | 同花顺 `block_top`（含连续上榜天数） | 无（只用涨停原因聚类） |
| 昨日涨停今日表现 / 强势股 / 次新 | 东财 `getYesterdayZTPool` / `getTopicQSPool` / `getTopicCXPooll` | 无（对应指标留空） |
| 人气榜 | `DataFetcherManager.get_hot_stocks`（东财人气榜 → 飙升榜 → 雪球） | 无（F 维度降级） |
| 日 K | `chart_service.get_kline`（同花顺行情） | 无（反包形态标「未经确认」） |
| 题材新闻 | `NewsSearchService.search_all`（财联社 / 同花顺 / 东财等，无需 key） | 无（故事空间按规则估计） |

- 同花顺池接口**不带连板数**，`high_days`「21天12板」是 N 天内 M 次涨停，不一定连续；连板数只能从天梯拿。
- 同花顺首封 / 末封时间是 epoch **秒**字符串；东财是 `92500` 这样的整数，价格单位是**厘**。
- 东财 `getYesterdayZTPool?date=X` 返回的是「X 的上一交易日涨停股在 X 当天的表现」。
- 两边口径不同：东财含北交所（92xxxx）与 ST，统一先过滤再计数。
- 东财炸板 / 跌停池只保留约 30 个交易日，所以池子按日落库（`daban_pool_rows`）。
- 上游可能返回 HTTP 200 + 截断 body，解析失败当上游异常处理，不当空池。
- 盘中生成标 `intraday`：周期结论是临时的，不写推荐记录，避免污染两派战绩。

## 生成为什么走后台任务

一次生成要打十几个上游、拉最多 40 只候选的日 K、搜 4 个题材的新闻，再调一次模型，实测 30–80 秒；首次生成还会按日回补近 20 个交易日的周期指标（不调模型）。这超过前端 30 秒的 HTTP 超时，所以与行业资金一样：`POST /jobs` 提交、`GET /jobs/{id}` 轮询，结果落库后由 `GET /overview` 只读返回。两次生成之间有冷却（`DABAN_REFRESH_COOLDOWN_SEC`）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/daban/status` | `{"enabled": bool}`，左侧菜单用 |
| GET | `/api/v1/daban/overview?trade_date=YYYY-MM-DD` | 只读快照；没有完整复盘时 404 `not_generated` |
| GET | `/api/v1/daban/history?limit=10` | 阶段条带（含回补记录） |
| POST | `/api/v1/daban/jobs` | 提交生成，body 可带 `trade_date`；返回 `reused` / `cooling_down` 三态 |
| GET | `/api/v1/daban/jobs/{id}` · `/api/v1/daban/jobs` | 轮询 / 当前进行中的任务 |
| POST | `/api/v1/daban/push` | 推送最近一份复盘（需 `DABAN_PUSH_ENABLED=true`，按交易日去重） |

## 配置

全部有默认值，不配置也能用。说明见 `.env.example` 的「我是打板王」段：`DABAN_ENABLED`、`DABAN_REFRESH_COOLDOWN_SEC`、`DABAN_LLM_TIMEOUT_SEC`、`DABAN_REASONING_EFFORT`、`DABAN_MAX_ACTIONABLE`、`DABAN_INCLUDE_BSE`、`DABAN_RULES_FILE`、`DABAN_RETENTION_DAYS`、`DABAN_PUSH_ENABLED`、`DABAN_AUTO_GENERATE`、`DABAN_AUTO_PUSH`。

`DABAN_RULES_FILE` 指向一个 YAML，只写想改的键，与内置默认值深合并，例如：

```yaml
stage:
  ice: {zt_max: 35}
  retreat_override_dt: 25
gates:
  chen:
    M3: {ferment: actionable}
```

盘后自动生成需要同时开 `SCHEDULE_ENABLED=true` 与 `DABAN_AUTO_GENERATE=true`：交易日 15:30 后每 10 分钟检查一次，当天还没有正式复盘就生成一次。
